4 common misconceptions

✗ Misconception

"HC-05's TX should connect to Arduino's TX, since both are 'transmit' pins."

✓ Reality

A transmitter must always connect to a receiver. HC-05's TXD (its output) connects to Arduino's RX pin (its input), and HC-05's RXD (its input) connects to Arduino's TX pin (its output). Connecting TX to TX means neither device ever receives anything.

✗ Misconception

"I need to write code that counts characters and cuts the message off at 16."

✓ Reality

The LCD library already handles this — lcd.print() simply stops outputting characters once the cursor reaches the display's column limit. No manual truncation logic is needed in the sketch.

✗ Misconception

"This project needs a custom-built Android app to work."

✓ Reality

HC-05 is generic — any app that can open a Bluetooth serial connection and send text works, including free "Bluetooth Terminal" apps already on the Play Store. Building a custom app is an optional later upgrade, not a requirement to get the core project working.

✗ Misconception

"SoftwareSerial is basically the same as the regular Serial object, just with a different name."

✓ Reality

SoftwareSerial emulates serial communication using regular digital pins and careful timing in software, rather than using Arduino's dedicated hardware UART. It's slightly less reliable at very high baud rates, but at HC-05's standard 9600 baud, it works reliably for this kind of project.
